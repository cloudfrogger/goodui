# GoodUI token source and sync

`penpot.tokens.json` is a snapshot of the connected GoodUI Penpot file (`a552d28a-7556-80e4-8008-d3392c96c899`) in Penpot's single-file token JSON format. It contains the existing `layout` and `layout-dark` sets, their appearance themes, and token aliases. Its values were read from Penpot through MCP. This file is the repository input for generated CSS; it is not a live connection to Penpot.

## Refresh from Penpot

1. In the GoodUI Penpot file, use **Tokens → Tools → Export → Single JSON file**. Save the export as `design-tokens/penpot.tokens.json`. Keep the set names `layout` and `layout-dark`, the `appearance/light` and `appearance/dark` themes, and their order. The MCP token catalog can also be used to inspect or capture the same values, but the current MCP interface does not write the Penpot export directly into this repository.
2. Run `npm run tokens:generate` from the repository root. This writes `angular/projects/goodui/src/tokens.generated.css` from the JSON snapshot. `npm run tokens:check` verifies that the generated file matches the snapshot. `npm run build:demo` regenerates it before compiling the library.
3. Review the generated CSS, both Penpot themes, and the rendered demo. Commit the JSON and generated CSS together only after review.

The direction is **Penpot → exported JSON → generated CSS/Tailwind variables → Angular package**. Exporting from Penpot and replacing the JSON file are manual steps; there is no automatic bidirectional sync. The generator preserves `{token.alias}` as `var(--good-token-alias)` and retains separate light and dark values. It rejects missing aliases, cycles, mismatched types, and unsupported token types.

Button tokens keep visual roles separate: `color.brand` feeds `button.default.background`; `button.destructive.background` is `#DC2626` with a dedicated white foreground; `button.secondary.background`, outline border, and ghost foreground alias existing neutral roles. Size tokens control height, icon size, inline padding, and icon-label gap. The dark set only overrides secondary hover; the other Button roles resolve through the active shared or dark color aliases. The Penpot variant boards bind these tokens to the applicable fills, strokes, dimensions, and flex properties.

Switch uses separate sizing tokens for its track and thumb at `small`, `default`, and `large`. `switch.on.background` aliases `color.brand` in light mode and has a dark override; `switch.off.background` also has a dark override. `switch.error.border` aliases `color.error`, whose light value is `#DC2626` and dark value is `#F87171`. The track and thumb bind their dimensions, fills, and track radius to these tokens. Error variants bind their stroke color. Disabled opacity is a fixed state treatment of 0.45 in Penpot and CSS; it is not a color token.

Input tokens in the live Penpot `layout` set and this snapshot have the same names, types, values, and aliases. `radius.control` aliases `radius.button` at 6 px, and `radius.compact` is 4 px. Input control heights and icon sizes alias Button's three-size scale. Padding and gaps also alias Button's corresponding size roles. Input surface, border, text, placeholder, readonly, addon, error, and focus colors refer to semantic color tokens. Generated CSS and the demo resolve those aliases in both themes. The 21 Input variants, 24 addon variants, and two compositions have live Penpot bindings. [Input variant IDs](../design/input-variants.json) map them to the Angular control.

Dropdown tokens cover popup width, inner padding and gap, trigger-to-popup gap, row height and padding, icon sizes, submenu width, and semantic surface, border, text, icon, hover, header, and badge colors. The Panel and Item Penpot families bind supported fills, strokes, dimensions, spacing, and radii. The 16 Dropdown variants reuse Button and Panel instances; the four Panel variants reuse Item instances. [Dropdown variant IDs](../design/dropdown-variants.json) map the published visual states to `good-dropdown`.

Badge tokens cover seven semantic color roles, three treatments, two shapes, and three size scales. `secondary` solid aliases the secondary Button, while `text` follows the theme text token. Warning, success, and info have explicit light and dark values. The Penpot boards bind their visual properties to the same tokens that generate the CSS; the generator also supports Penpot `fontSizes` tokens for Badge text. [Badge variant IDs](../design/badge-variants.json) map all 126 published combinations to `good-badge`. The live Penpot catalog and repository snapshot were compared after Badge work: 197 `layout` and 34 `layout-dark` tokens matched by name, type, and value. A temporary base-color change and a temporary semantic-alias change both propagated to the bound Badge fill, then were restored.

Checkbox and mono Switch add theme-aware aliases in the `layout` set. Mono Switch on uses `color.text` for the track and `color.surface` for the thumb; its off thumb uses `color.text`. Checkbox selected colors use either the brand Switch on color or `color.text`, with inverse marks. Unchecked background uses `color.surface`. Box and mark sizes and the compact radius are semantic tokens. [Switch IDs](../design/switch-variants.json) and [Checkbox IDs](../design/checkbox-variants.json) map their 36 variants each to the Angular inputs. The imported Penpot SVG path geometry is fixed per size because the SVG group itself cannot receive a sizing-token binding; its wrapper board is token-bound.

After these additions, the live catalog and JSON snapshot match across 214 `layout` and 34 `layout-dark` tokens. A temporary base `color.text` change moved the mono Switch and Checkbox colors together; a temporary `checkbox.mono.selected.background` alias change moved the bound Checkbox fill to brand blue. Both values were restored and the light theme reactivated.

Radio Group adds 15 semantic `radio.*` tokens in `layout`: separate background, border, selected color, indicator and dot sizes, radius, and flex gaps. Its brand selected color aliases the theme-aware Switch on role; mono selected color aliases `color.text`. The MCP catalog and JSON snapshot now match across 229 `layout` and 34 `layout-dark` tokens. The 24 [Radio Group variants](../design/radio-group-variants.json) bind their indicator and dot sizes, fills, strokes, rounded corners, and layout gaps to those tokens. A temporary `color.text` change updated the mono dot, and a temporary `radio.mono.selected.color` alias change updated it to brand blue. Both were restored. Dark mode resolved brand selection to `#3B82F6`, mono selection to `#FAFAFA`, and the indicator surface to `#09090B`; Penpot was returned to light mode on `02 Layout`. The Penpot export is copied into `penpot.tokens.json` manually through MCP; `npm run tokens:generate` then generates the CSS variables.

Card and Link add 22 semantic tokens to `layout`, giving the repository snapshot 251 `layout` and 34 `layout-dark` tokens. Card frame, Header and Footer surfaces, padding, gaps, and heights have separate roles even where their values match. Link accent and mono colors alias `color.accent` and `color.text`. Card Header default and secondary fills alias `color.surface` and `color.selected`; the footer and body colors follow their semantic text roles. The Penpot variants bind supported shape properties to these roles, while the image is an application-owned media fill. [Card IDs](../design/card-variants.json) and [Link IDs](../design/link-variants.json) map the published variants to Angular. Re-export Penpot tokens and regenerate CSS after design changes; the snapshot does not update itself.

Shell state and responsive designs are separate main components. Button is a Penpot variant group with 45 `variant` × `size` × `content` combinations. Its ID mapping is in [button-variants.json](../design/button-variants.json); the original outline IDs and instance relationships stay intact. The selected semantic bindings are listed in the [design contract](../design.md) and [token guide](../doc/docs/foundations/tokens.md).

Switch is a Penpot variant group with 18 `state` × `size` × `status` combinations. The [switch variant map](../design/switch-variants.json) records the published library component IDs, which differ from the corresponding board shape IDs on the canvas. Each variant is a main component and maps to `good-switch` inputs and runtime state.

## Verification and current limits

The live MCP catalog and this snapshot were compared token by token after the Button additions: all 66 names, types, values, and theme set selections matched. The generator produced the same base values and preserved alias references. Temporary changes of `space.7_5` from 30 to 31 and `main-menu.gap` from `{space.2_5}` to 11 changed the bound desktop Topbar padding and MainMenu gap in Penpot after theme re-evaluation, including the composed AppLayout. Both tokens and the light theme were restored, then checked at 30 and 10. Penpot's plugin API did not immediately refresh bound shape properties on a token value assignment; switching the appearance theme caused the expected re-evaluation.

After adding Switch, the live catalog contains 71 tokens in `layout` and 13 in `layout-dark`. The new values and aliases were captured from the Penpot MCP catalog into the JSON snapshot. All 18 Switch boards were checked for main-component status, dimensions, thumb position, size and color token bindings, and disabled opacity. Changing base token `color.error` temporarily from `#DC2626` to `#C026D3` changed the bound error stroke; changing semantic token `switch.error.border` temporarily from `{color.error}` to `{color.brand}` changed it to brand blue. Both values and the light theme were restored, and the stroke returned to `#DC2626`. Browser inspection confirmed the generated error color is `#DC2626` in light mode and `#F87171` in dark mode.

After adding Input and the shared action radius, the live catalog and this snapshot each contain 103 `layout` tokens and 13 `layout-dark` tokens. Main Input boards bind height, horizontal padding, gap, radius, fill, and stroke; file buttons bind their own height and padding; addon icon variants bind width and icon size. All 18 Switch tracks now use flex layout with `switch.thumb-inset` bound to each padding edge. All rounded main-component boards on `01 Components` have semantic radius bindings, including circular triggers using `radius.action`. In Penpot, temporarily changing base token `radius.button` from 6 to 7 changed Input's `radius.control` corner to 7; changing semantic token `input.error.border` from `{color.error}` to `{color.brand}` changed the error stroke to brand blue. Both values were restored and light mode reactivated. Dark mode showed `#F87171` error strokes and `#18181B` readonly and contrast addon surfaces.

After adding Dropdown, the live catalog and snapshot each contain 121 `layout` tokens and 13 `layout-dark` tokens. All 12 Item boards bind height, padding, and radius; all four Panel boards bind width, padding, gap, surface, border, and radius. Temporarily changing base token `space.2_5` from 10 to 11 changed Item padding from 10 to 11, and changing semantic token `dropdown.panel.background` from `{color.surface}` to `{color.selected}` changed the Panel fill from white to `#F4F4F5`. Both values were restored. Dark mode resolved the Panel to `#09090B`, border to `#27272A`, item text to `#FAFAFA`, and badges to `#18181B`.

Some preexisting geometry differs between Penpot compositions and responsive CSS. For example, the Penpot mobile MainMenu retains a 10 px gap while the Angular mobile breakpoint uses 4 px; the Penpot TopbarMenuContainer uses a 10 px flex gap while the Angular desktop layout uses 26 px. These are not mapped to one semantic token. Align those designs explicitly before adding shared tokens for them. Absolute-positioned Penpot boards cannot bind spacing tokens to their manual offsets; keep those values explicit until the layout model is intentionally changed.
