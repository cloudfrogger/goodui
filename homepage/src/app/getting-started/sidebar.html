Sidebar Declare navigation where it belongs, with automatic active links and one responsive sidebar. Declare your navigation Place good-sidebar directly inside good-app-shell. Add good-sidebar-item children for links, and nest items to make expandable groups. Use good-sidebar-menu-container when a group needs a section heading. The sidebar owns its branding, spacing, scrolling, and nested guide lines. Try the example below. Documentation contains the current Sidebar page, so GoodUI opens that ancestor and marks its link automatically. Select Header menu to navigate to a sibling chapter. Compose the application shell The shell arranges your Sidebar, AppHeader, and routed page. It no longer accepts navigation arrays. Header navigation belongs in good-header-menu inside good-app-header; sidebar navigation belongs in good-sidebar. Brand inputs on the shell are shared defaults that either child can override. On mobile, the header's sidebar button opens the same Sidebar instance in a modal drawer. Escape, the backdrop, Close, or navigation dismisses it and restores focus. Resizing preserves the sidebar's projected content and state. Routes and keyboard behavior Use route on leaves and label on parent groups. GoodUI reads the Angular Router, highlights active links, and opens their ancestors. Set activeMatch="exact" for an overview route that prefixes other pages. No active-route binding is needed. Parent buttons expose aria-expanded and aria-controls. Enter and Space toggle them; Tab skips collapsed children. Give separate sidebars distinct label values so their navigation landmarks remain identifiable.
