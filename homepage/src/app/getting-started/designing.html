Getting started Designing with GoodUI and an AI agent Prompt your own screen in Penpot with the GoodUI design library. Then prompt Codex or Claude to implement that design with the GoodUI Angular library. This workflow has two creative steps: first describe the screen you want and review your linked Penpot design; then ask the agent to turn that exact design into a working Angular page. The GoodUI skill and catalog connect the design components to real Angular APIs. 1. Prepare an Angular app and matching references Follow Developing to install the locally built @goodui/angular package and import @goodui/angular/styles.css. Then use the AI package from the same GoodUI version and source revision. The full package gives the agent local component details and examples, so it can read only what this page needs. When a matching GoodUI release provides goodui-ai-<version>.zip, download that archive and extract it into .goodui/ in your app. If you installed GoodUI from a source checkout as shown in Developing, create the same archive from that checkout. This example assumes sibling folders named goodui/ and hello-goodui/: Check that the version printed by the command matches the archive name. If it does not, get the matching package instead of using newer master documentation for an older installation. The small release ZIP contains only the skill; the full ZIP is the useful choice when you want quick, low-context prompting with local references. 2. Make the skill available to your agent Run the command for the agent you use from your Angular app's root. Keeping the skill in the project makes the setup visible beside the app and easy to update with GoodUI. Start a new agent session after copying it, and mention .goodui/ai in your first prompt so it finds the local catalog. Codex: place the skill at .agents/skills/goodui/SKILL.md. Claude Code: place the same skill at .claude/skills/goodui/SKILL.md. Copy both if your team uses both agents. The skill is the entry point, not a copy of every component manual. It first checks the installed GoodUI version and then loads only the relevant catalog files, guides, and examples. See the AI package instructions when updating the package. 3. Make the GoodUI Penpot library available Get access to the live GoodUI Penpot file in your workspace. Publish or enable it as a library in your target design file, then choose its components from the asset library. Start with the application shell, then add linked cards, tables, fields, and actions. Select published variants and shared tokens for light and dark appearances; keep instances linked so later library updates remain traceable. Connect your agent's Penpot MCP integration and give it access to the target file and GoodUI library. The skill does not connect Penpot by itself. Ask the agent to inspect the live components before editing and to report the component names it used. The AI ZIP contains mapping references, not a native .penpot library archive. If access is missing, establish the connection before asking for the design. The design-to-code guide records the published Penpot families and their Angular owners. 4. Prompt your own Penpot screen Give the agent a user task, the information to show, and the interaction you expect. Ask it to compose your screen with linked GoodUI Penpot components and to show desktop and mobile states. Review this design before requesting code. 5. Prompt the Angular implementation of that design Give the agent the Penpot screen from step 4 and ask it to implement that screen in your Angular app, primarily with the GoodUI Angular library. The catalog supplies exact imports, selectors, inputs, outputs, and form behavior. GoodUI layout components provide the application frame and spacing. 6. Review the rendered result and refine it Open the page and check the actual content, not just a successful build. Look at mobile and desktop widths, light and dark themes, keyboard focus, and the main interaction. Give the agent one concrete correction at a time. Reusing a small set of GoodUI components and local references keeps each iteration focused and avoids repeatedly sending the entire design system to the agent. Repeat this screen-by-screen. The registration example shows how a complete form uses the same GoodUI controls, layout, validation, and displayed source code.
