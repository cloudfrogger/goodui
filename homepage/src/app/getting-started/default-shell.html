Render a scrolling page layout="page" is the default. MainView adds a shared inset of 32 px on every side, reduced to 16 px horizontally at 640 px and below, and lets the content scroll. Put every top-level content block in a direct good-section to align the heading and content to one centered reading width. Use the available width Direct Sections make a centered reading page, as shown above. For a scrolling page that uses the available width, put the content directly inside MainView. Its heading and content then start at the same left edge. The layout="page" value can be omitted because it is the default. For a workspace that fills the remaining inner height without page scrolling, use the fill option described below. Fill option: use the remaining inner height Fill is a variant of the same layout. Set layout="fill" on MainView to give one workspace the remaining inner height. Page and fill layouts share the same responsive inset, so headings and workspace containers align. The sidebar and topbar stay in place; the workspace owns its scrolling. Place one primary workspace directly inside MainView. Its content scrolls internally, while the application frame stays fixed. For Calendar, [fillHeight]="true" makes the calendar fill MainView and keeps its time grid, month view, and list scrolling within the component. Put the workspace directly in MainView without a redundant Section or Card. An optional Heading 1 and Summary form a compact title block above it, followed by a 24 px content gap.
