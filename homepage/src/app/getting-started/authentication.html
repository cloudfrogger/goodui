Getting started Authentication Use OpenID Connect for sign-in, role guards for protected routes, and server-side authorization for your API. Keep Keycloak visually consistent with the GoodUI theme. Your application owns its identity-provider integration, session handling, and permissions. GoodUI supplies the interface components for that application. Use OpenID Connect We recommend OpenID Connect (OIDC) with Keycloak or another identity provider. Use Authorization Code Flow with PKCE S256 for Angular browser clients. Let a maintained OIDC client handle sign-in, callbacks, and sessions. The Keycloak JavaScript adapter guide describes this integration. Use a public client with client authentication disabled, HTTPS, and specific redirect URIs and web origins. Keep client secrets on the server. The Keycloak client configuration guide explains these settings. Initialize Keycloak before starting Angular and its router. Replace the example identity-provider URL, realm, and client ID with your configuration. This example requires sign-in before the app starts and makes the initialized adapter available through Angular injection. Keep the router and provideGoodUI() providers from Developing in appConfig. Protect routes with role guards Apply a role guard to each protected route. The guard below checks authentication and a client role for the configured application client, then returns Angular's access-denied route when access is refused. Create and assign the administrator client role in Keycloak. Applications that use realm roles can check hasRealmRole() instead. Implement the administration and access-denied page components referenced here. Keep the access-denied route accessible so a refused navigation can reach it. Menu visibility and available actions can follow the same role information. Angular documents guard return values and navigation behavior in its route guards guide. Enforce permissions in the API Enforce authorization on the server for every protected operation, including roles and ownership of the requested resource. Send the access token to its intended API over HTTPS. Validate its signature, trusted issuer, intended audience, and expiry before using its claims. Use your backend's supported OIDC/JWT middleware and configure the expected realm and API audience. The JWT access-token validation rules describe these checks. Keep access and refresh tokens in the OIDC client's managed session, handle expiry and logout, and attach tokens only to the configured API origin. Keycloak's JavaScript adapter keeps its tokens in memory. The adapter documentation covers token refresh and session handling. A Keycloak theme that matches GoodUI exactly We provide a Keycloak theme that matches the GoodUI style exactly. Sign-in, registration, account management, and administration share GoodUI's colors, typography, rounded controls, and light/dark appearance. Get it from the GoodUI Keycloak theme repository. The theme validates custom color input as six-digit hexadecimal values and serves its appearance initializer from the Keycloak origin. Its appearance controls preserve OIDC parameters and existing CSP requirements. The repository documents these security measures. Install the theme on your Keycloak server and select goodui under Realm Settings → Themes for the required areas. Configure the same logos and colors as your application. Use the documented theme_mode option to carry Light, Dark, or System appearance into sign-in. Follow the repository's installation and branding instructions.
