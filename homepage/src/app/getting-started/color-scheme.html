Foundation Color Scheme The shared color roles behind GoodUI's light and dark themes. GoodUI's Penpot layout set defines the base colors. The layout-dark set overrides colors that need a different value in dark mode. Components refer to semantic roles such as color.brand or color.error, so changing a role updates its linked uses. Dark mode pairs an anthracite canvas with slightly lighter surfaces and soft gray text. Primary text has an 11.99:1 contrast ratio on the canvas; muted text has 6.91:1. The shared dark text pairs are checked against the WCAG 2.0 AA minimum of 4.5:1 for normal text. The swatches below read the active CSS variables. Use the button to switch between Light and Dark; the values also respond to color overrides in a consuming app. Appearance: {{ theme.theme() }} Contrast and color choices Choose foreground and background together. Check at least 4.5:1 for normal text at WCAG AA, or 3:1 for qualifying large text (24 CSS pixels, or about 18.67 CSS pixels in bold). A 26 px page title qualifies; a 14 px description does not. Enhanced text contrast at AAA uses 7:1 and 4.5:1 respectively. Compare the unrounded ratio, including the actual effects of opacity and overlays. The dark palette uses canvas #18181B, surface #1F1F23, primary text #D4D4D8, and muted text #A1A1AA. On the canvas these text colors reach 11.99:1 and 6.91:1. Selected surfaces use #2A2A30; their primary and muted text reach 9.65:1 and 5.57:1. The softer contrast is deliberate, with room above the normal-text AA threshold. Use semantic roles for body text, descriptions, surfaces, status, and focus. Yellow color.warning is a vivid status fill; use color.warning-foreground for small warning text. Keep marker colors for categories and pair them with a visible label, shape, pattern, or icon. Do not convey required information with color alone. Keep links recognizable with wording and decoration, not only a different hue. Text contrast does not prove control contrast. Essential control boundaries, state indicators, and graphical information need their own 3:1 checks under WCAG 2.2, with its applicable exceptions. Verify focus rings, disabled and error states, transparent surfaces, and both themes. Decorative separators and inactive controls have different requirements; do not treat every subtle divider as a failing text background. The repository command npm run check:contrast checks 64 defined dark text pairs, including status text, neutral Badge labels, and Calendar marker labels. It does not cover every light-theme state, non-text boundary, image, application override, or combination. The ISO/IEC 40500 table records this verification limit instead of presenting a full-framework conformance claim. Customize colors in your app Penpot color.* roles become CSS --good-color-* variables. The shorter --good-brand style aliases and Tailwind --color-good-* mappings use those roles. Brand and accent share the default light blue but serve different purposes; accent becomes lighter in dark mode. Overlay opacity is controlled separately by the component using it. Import GoodUI's stylesheet into your application's global stylesheet, then override the --good-color-* variables after the import. Add dark-mode overrides under [data-theme="dark"]. Component colors that use those roles follow automatically; explicit component colors, such as the primary Button hover color, can be overridden separately. GoodThemeService selects the appearance. It uses a saved choice first and the system preference when there is no saved choice. The selector shows the active Light or Dark theme and saves your choice. Applications can call setTheme('system') to clear that choice and follow operating system changes again. Keep Penpot and code aligned App-level CSS overrides change the running app only. To publish a shared GoodUI palette, change the matching tokens in Penpot, export the token JSON to design-tokens/penpot.tokens.json, then regenerate the CSS and verify the homepage. The export is a manual step; there is no live synchronization.
