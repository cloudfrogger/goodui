Getting started Developing with AI Install the GoodUI skill, give your agent the matching component references, and describe the screen you want to build. You can describe a page in everyday language. The GoodUI skill helps your coding agent choose the components and look up their real Angular APIs. Follow these steps in the Angular project where you want to use GoodUI. 1. Install GoodUI in your application Open a terminal in your Angular app's root, beside its package.json, and run the command below. If you are starting a new app, follow Developing first to create it and initialize the GoodUI services. Add this import to your app's global src/styles.css if it is not there yet. The npm package includes the skill and its reference files. They are available at node_modules/@cloudfrogger/goodui/ai/. That gives the agent the catalog, guides, examples, and source references for the version your app actually uses. 2. Install the skill for your coding agent Stay in your Angular app's root and run the command for your agent. For Codex, use this command. It creates .agents/skills/goodui/SKILL.md in your project. For Claude Code, use this command. It creates .claude/skills/goodui/SKILL.md. Run both commands if your team uses both tools. Start a new agent session in this project after installation. The skill tells the agent where to find the reference files in the installed npm package. Keep the generated skill file in your repository so teammates get the same entry point; they install the locked dependencies with npm ci. If the installer reports that ai/install.mjs is missing, your installed GoodUI version predates bundled references. Upgrade to a version containing them. If a different GoodUI skill already exists at the destination, review that file before replacing it with the installer's --force option. 3. Check that the agent can find GoodUI Send this as your first message. The response should name your installed version, report the available selectors, and point to concrete component guides. This gives you a quick way to check the setup before asking for a whole page. In Codex you can explicitly invoke $goodui; in Claude Code use /goodui. You can also ask in plain language to use the GoodUI skill, as the prompts on this page do. The agent can read the catalog and relevant files from your workspace. 4. Describe the first screen Tell the agent what people need to do, which information belongs on the screen, and which interactions should work. Start with one page. You can copy this prompt and replace the directory, columns, and actions with your own requirements. The catalog covers the published Angular component and directive selectors. Each detail file records the available inputs, required values, outputs, projection slots, and form integration. The agent also has the exported types, service source, and usage examples, so it can look up how components fit together while implementing your request. 5. Add behavior in small steps Once the directory works, ask for its next interaction. This prompt adds an edit flow with a modal, real form validation, and local state. You can name a GoodUI component yourself or describe the behavior and let the agent find the matching controls. When your application has a backend, tell the agent which API client and endpoints to use and what loading, error, and success behavior you expect. The component guides supply the UI contracts; your project supplies its data and business rules. 6. Review the page and give concrete feedback Open the page and try its main action. Check a narrow window, keyboard use, and both themes. Describe the visible problem and desired result so the agent can adjust the documented component options. For later sessions, you can add the following paragraph to your project's existing AGENTS.md for Codex or CLAUDE.md for Claude Code. Add it alongside your project's own instructions. 7. Keep the skill and package together When you update GoodUI, its bundled references update with it. Run the installer again to refresh the project skill too. This example updates the Codex copy; use --agent claude for Claude Code or --agent both for both. The --force option replaces the existing GoodUI skill file, so review any custom edits there first. Commit the updated package lockfile and generated skill file together. Your next agent session can use the references shipped with that exact installed version. Work from a Penpot design If you want to design the screen in Penpot first, continue with Designing. The same skill knows the component mapping. Give the agent access to the live GoodUI library and your target file through its Penpot integration, then ask it to inspect the design before implementing it. For the agent tools' own skill discovery and invocation rules, see the Codex skills guide and the Claude Code skills guide.
