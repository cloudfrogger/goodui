Examples · Case studies Webmailer Two connected screens show how generic GoodUI components form a mail workflow. Start with the mail workspace to browse folders, select a message, and open the composer. Then use Compose mail to edit a draft. Both pages are live examples; their mail data and commands belong to the example, while the controls remain reusable across applications. 1. Browse and act The workspace uses good-main-view layout="fill" with an good-action-bar in its toolbar slot. The bar groups commands and keeps search and filtering on the right. Below it, nested good-resizable panes arrange a borderless folder good-listbox, a compact selectable good-table, and a message preview. Selection, unread emphasis, and command events are GoodUI APIs; the message array and the action handlers are application state. Open the mail workspace. Choose a folder and a message, resize the panes, search, and try a command. Use its View source command to inspect the complete Angular template and TypeScript. 2. Compose a draft The composer also fills the main area. A good-rich-text-editor receives the draft through [(value)] and owns the editing tools. Its header projects a native form goodForm with GoodUI fields; its footer projects GoodUI actions. The example validates recipient and subject locally. Sending requires an application mail service. Open Compose mail and edit the draft. The Rich text editor chapter explains its formatting features, HTML value, and feature selection. Use this case study Use the Webmailer when designing or implementing a related workflow. Read the relevant screen and its source first, then consult the component chapters for exact APIs. If the workflow exposes a missing capability, add it to the generic GoodUI component and update the case study to show its use. Other case studies need no review unless their behavior is affected.
