Header actions Compose the actions in the upper-right corner of the application header. good-header-actions is the container for the right-hand side of the header. Place independent actions inside it in the order you need. The example shows Search, Notification, and Avatar; Theme toggle is an optional fourth action. Import the container and each action in the component declaring this template. The same composition works inside a standalone good-topbar. The container owns alignment and responsive gaps. Configure projected children directly; remove or reorder tags to choose the available actions. With no projected content, Header actions supplies Search, Notification, Theme toggle, and Avatar. Existing data inputs remain searchItems, notifications, user, and avatarActions. Visibility inputs showSearch, showNotifications, showThemeToggle, and showAvatar default to true. Optional showSettings defaults to false. These inputs configure the generated defaults; configure custom children on their own tags. The following sections document Search, Notification, Avatar, and Theme toggle as independent components, each with its own working example and API. Header search · good-header-search GoodHeaderSearchComponent opens a modal navigation search. Supply items: readonly GoodSearchItem[], which defaults to an empty array. Matching ignores letter case and searches labels and descriptions locally. An empty query shows all items; an unmatched query shows “No results.” Try “Tables” or “pagination.” Show the search shortcut Set [hotkey]="true" to show a wide search button with a magnifier, “Search…,” and a keyboard hint. Press Ctrl+K on Windows/Linux or ⌘K on Mac to open the same search dialog. The default is false, which keeps the compact icon action. At viewport widths of 1200 px and below, the button becomes a compact magnifier while the shortcut remains active. Enable this option on one search, usually in your application header. If several visible searches opt in, the first registered instance handles the shortcut. An already-open modal keeps keyboard focus; hidden instances and shortcuts claimed by another handler are skipped. Use unique stable IDs and configure Angular Router. Opening focuses the field. Tab and Shift+Tab move between controls and results; Enter follows a focused result. Escape and Close restore focus to the trigger. Public open() and close() methods control the dialog. For a permanently visible page search field, use Input with type="search". Header notification · good-header-notification GoodHeaderNotificationComponent is the bell and notification inbox. The badge counts unread messages. It combines entries from GoodNotificationCenter with optional items: readonly GoodNotification[], which defaults to an empty array. Add notification Register provideGoodUI() once. AppLayout already includes a notification host; applications without AppLayout need one good-notification-host for toasts. Public open() and close() control the inbox. Escape and Close return focus to the bell. See the Notifications example for progress, delivery, actions, and acknowledgements. Header avatar · good-header-avatar GoodHeaderAvatarComponent owns the avatar trigger and account menu. It shows an avatar image or initials, identity details, navigation links, nested actions, a Dark Mode switch, and optional sign-out. The user input accepts GoodUser | null and defaults to null; actions accepts readonly GoodMenuAction[] and defaults to an empty array. GoodUser supports name, email, initials, avatarUrl, and badge. Actions support id, label, icon, route, action, children, detail, separatorBefore, and variant. Supply children for submenu parents. The host application implements sign-out. Escape closes nested menus before the account panel and returns focus to the trigger; outside clicks close the panel. Header theme toggle · good-header-themetoggle GoodHeaderThemeToggleComponent cycles Light → System → Dark → Light. It has no inputs. Its icon represents the selected preference, and its accessible label announces the current and next mode. Enter or Space activates the button. Current mode: {{ theme.preference() }} GoodThemeService.preference() returns light, system, or dark; theme() returns the resolved appearance. Explicit choices are stored in the goodui-theme cookie; System removes that cookie and follows the device. The Developing chapter explains how to avoid flickering on page load with an early theme and background-color snippet. Update existing applications Replace good-main-menu with good-header-actions, good-search with good-header-search, good-notifications with good-header-notification, good-avatar-menu with good-header-avatar, and good-theme-toggle with good-header-themetoggle. Import the matching GoodHeaderActionsComponent, GoodHeaderSearchComponent, GoodHeaderNotificationComponent, GoodHeaderAvatarComponent, and GoodHeaderThemeToggleComponent classes. Inputs and behavior are unchanged. The former selectors and class names are replaced by these public names.
