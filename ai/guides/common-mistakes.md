# Common mistakes

- **Guessing API names:** Open `ai/catalog/index.json`, then the selected detail file. Import the listed symbol from `@cloudfrogger/goodui` and use the recorded selector and inputs.
- **Using an old catalog with another package version:** Compare the installed `@cloudfrogger/goodui` version with the AI package. For a mismatch, fetch the exact matching release/tag or commit; never substitute `master` silently.
- **Treating `model()` as an ordinary input:** Its `nameChange` output is generated by Angular. For forms, prefer `formControlName` on components with `forms.controlValueAccessor: true`.
- **Adding a field without its required label:** The catalog marks required inputs. A hidden visual label still needs an accessible name.
- **Duplicating shell spacing or heading markup:** Use MainView and Group ownership as described in `layout.md`.
- **Assuming every Penpot shape is a public selector:** `penpot.kind` distinguishes component and internal part; absent mappings are marked in `missing`.
- **Assuming a successful TypeScript build proves usability:** Check keyboard focus, form errors, dark theme, and narrow screens in a browser.

- **Assembling showcase specimens into a workflow:** Start with the closest complete example and preserve its useful hierarchy; use the catalog to verify the exact APIs.
- **Choosing controls before the composition:** Inspect the user's reference for region sizes, reading order, density, and action placement. A different widget exposing the same commands may still produce the wrong workflow.
- **Wrapping every block in another frame:** Give Section, Group, Card, and Table distinct jobs. Use an embedded Table without an extra frame when the enclosing section already establishes the context.
- **Shrinking headings to fit actions on mobile:** Preserve readable heading width and let the documented page/section action areas wrap. Check the rendered result with realistic text.
- **Calling a page finished after a build:** Apply the concrete visual and interaction checks in [Designing a GoodUI screen](../../guides/layout/screen-design.md); state any unavailable check.

## Formatting money while typing

Do not bind a freshly formatted `toFixed()` string back into an Input after every keystroke: entering `50` can turn the first `5` into `5.00` and move the caret. Use CurrencyInput with integer minor units and let it format on blur. It accepts locale-aware decimals, rejects excess precision, and retains invalid drafts for correction. An ordinary NumberInput keeps numeric stepping and is not a currency field.

## Table header actions that collapse into a menu

Do not invent Table inputs such as `actions`, `headerActions`, or `actionSelected`: Table projects `[goodTableActions]`. For automatic overflow, import `GoodActionBarComponent` and project one `<good-action-bar goodTableActions appearance="compact" [groups]="commands()" (commandSelected)="runCommand($event)" />` directly into Table. Import `GoodActionBarGroup` and `GoodActionBarSelection` as types. Use Table's `[searchable]="true"` for integrated search; do not add a second search field or synchronize two queries.

ActionGroup with arbitrary Buttons still wraps; it cannot infer menu labels, disabled state, or handlers and does not provide automatic overflow. Keep command IDs stable, handle both group and command IDs, and use a computed group array when disabled state depends on signals. Do not mark every command `important`, because important commands stay visible and can scroll. Verify a narrow table inside a wide viewport as well as mobile; no application breakpoint, CSS layout rule, or duplicate mobile menu is needed. Start from `ai/examples/table-view.ts` and `.html`.

For a filled Table, set `[fillHeight]="true"` on Table and `layout="fill"` on its parent MainView. Do not put the entire Table in an application scroll wrapper: that would scroll title, search, actions, and pagination. A bounded parent is required; the boolean does not size arbitrary unbounded pages. Keep native headers and rows in one table for aligned horizontal scrolling and sticky grouped column headings. Check populated, loading, filtered-empty, and custom-empty states in the available height.

Use the global page rhythm: MainView has 32 px padding in both page and fill layouts, reduced to 16 px horizontally at viewport widths of 640 px and below. H1 is 26 px / 600 / 32 px; Summary is muted 14 px / 400 / 21 px supporting text, 8 px below the title. Leave 24 px after the full heading block before content. For a single table named by the page heading, omit Table's visible `title` and retain its accessible `label`; integrated search and compact actions share one toolbar with 16 px inner padding. Do not add compensating application CSS or negative offsets. See `guides/migrations/main-view-spacing.md` and the Table workspace example.
