# User registration example

The homepage's **Examples → User registration** page demonstrates a complete Angular Reactive Form using only GoodUI layout, content, and control components. It places GoodUI Breadcrumbs above the page heading with the path `Home › Examples › User registration`; Home links to the dashboard, and the final item is the current page. The example lives in [homepage/src/app/examples/user-registration](../../homepage/src/app/examples/user-registration/): the [page](../../homepage/src/app/examples/user-registration/user-registration-page.ts) and [form](../../homepage/src/app/examples/user-registration/user-registration-form.ts) each have their own TypeScript class and HTML template. No example-specific stylesheet or Tailwind class is required.

The [showcase wrapper](../../homepage/src/app/examples/user-registration/user-registration-example-page.ts) projects four GoodUI CodeBlocks into the page's content slot. They display the actual page and form `.ts` and `.html` files, without the showcase code in the copyable example. `npm --prefix homepage run examples:sync` regenerates [source-code.generated.ts](../../homepage/src/app/examples/user-registration/source-code.generated.ts) from those four files; `npm --prefix homepage run examples:check` verifies it. The homepage's `start` and `build` scripts sync automatically before running. If you edit a source file while `ng serve` is already running, run `examples:sync` again to refresh the visible code.

The form collects a title choice (`Mr.`, `Ms.`, or `No title`); first, middle, and last names; street address, postal code, city, and country; optional phone and required mobile numbers; email; and a password entered twice. It uses `goodForm` with `fullWidth`, `good-group` for lightweight titled sections, and `good-form-row` for equal-width name, address, phone, and password fields. The three-column rows become two columns in a narrower container and one column on mobile. `good-form-field` owns labels and validation messages, while GoodUI Input, RadioGroup, Country Select, and Phone Input own the controls. The selected address country initializes both phone selectors, while users may choose another calling code in either phone field.

Submitting an incomplete form marks its controls as touched and displays GoodUI error text. The email uses Angular's email validator; a form-level validator requires the two masked password fields to match. A valid submission displays the user's name and email, omitting the passwords. This is a local demonstration: it does not create an account on a server or store credentials.

Future example pages should show their working template and TypeScript source, use GoodUI components for visible layout and controls, and identify a missing library capability before introducing page-specific CSS or Tailwind layout rules.
