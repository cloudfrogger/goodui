# GoodUI contributor instructions

## Project

GoodUI is an Angular UI library with a Penpot design system and an Angular homepage. The library is in `angular/projects/goodui`; `homepage` is an Angular app linked to the built package. Project prose, documentation, examples, and user-facing default strings use American English. Preserve stable public IDs and selectors unless a deliberate documented rename is requested.

Use `Cloudfrogger, Inc.` for copyright attribution throughout the project.

GoodUI is intended to be a generic, reusable UI framework. Review every component name and visual design for common use across unrelated products before adding it. Future projects will use the GoodUI Penpot components as a design library and the matching Angular package as their implementation. Keep a documented, unambiguous mapping from every published Penpot component family to its Angular selector, inputs, and variant/state semantics. Use domain-specific words only in example content, never in reusable component names. Verify the mapping whenever either side changes.

## Before editing

1. Read `design.md`, especially naming, tokens, component ownership, and open states.
2. Inspect the affected Penpot page through MCP before changing a design. Do not infer the current board from an older description.
3. Check `guides/` for existing component and design contracts, and inspect the corresponding homepage example before changing behavior or APIs.

## Design rules

- Penpot is the visual source. Maintain real Penpot library components with stable names and IDs.
- Keep `design/component-map.json` complete for every published Penpot UI component name and stable library ID, including its Angular selector, state, and internal owner where applicable. Keep variant IDs in their dedicated manifests. Run `npm run check:mapping` after changing either side, then compare the map with the live Penpot library through MCP. Internal Penpot parts must identify their owning Angular selector.
- Keep brand artwork on `04 Logos` separate from generic UI families. Record each published logo asset's Penpot ID and source PNG in `guides/contributing/design-to-code.md`; logo artwork has no Angular component selector. The light and dark wordmarks are editable Penpot vectors exported to `assets/brand/`; the other symbols and badges retain their raster backgrounds and effects. Keep the SVG exports aligned with their Penpot components.
- Keep `design/button-variants.json` aligned with the live `goodui.button` Penpot variant group. Preserve all 45 published library IDs and the `variant` / `size` / `content` mapping to `good-button`; update and verify the manifest when Button variants change.
- Keep `design/switch-variants.json` aligned with the live `goodui.switch` Penpot variant group. Preserve the original 18 brand library IDs and map all 36 `state` / `size` / `status` / `appearance` combinations to `good-switch`; verify mono colors, the theme-specific error token, and runtime accessibility.
- Keep `design/checkbox-variants.json` aligned with the live `goodui.checkbox` Penpot variant group on `06 Checkboxes`. Its 36 `appearance` / `state` / `size` / `status` combinations map to `good-checkbox`; verify native indeterminate-to-unchecked behavior, disabled controls, token bindings, and both themes. The mark wrapper boards must have no fill so their vector checks and dashes remain visible.
- Keep `design/radio-group-variants.json` aligned with the live `goodui.radio-group` Penpot variant group on `07 Radio Groups`. Its 24 `appearance` / `size` / `selection` / `status` combinations map to `good-radio-group`; verify native exclusive selection, disabled groups, semantic indicator and dot tokens, and both themes. The Penpot specimens show three choices; runtime option text and count are supplied through the Angular options array, not variant axes.
- Keep `design/rating-variants.json` aligned with `goodui.rating` on `15 Ratings`. Its 36 `icon` / `size` / `value` / `status` combinations map to `good-rating`; count and exact score are runtime values. Preserve linked Lucide instances, yellow star and thumbs-up, red heart, gray unselected, and custom color token bindings, three size tokens, native radio keyboard behavior, and both themes. Custom selected colors are a runtime override; the Penpot smile specimen is an example, not a published variant.
- Keep `design/table-variants.json` aligned with `goodui.table` on `16 Tables`. Its `style` / `state` variants map to `good-table`; optional search and pagination are parts of this selector, and cell content is runtime data. Preserve linked Badge, Switch, and action instances in the populated specimen, semantic `table.*` token bindings, and both themes. Verify client and manual sorting/filtering, numbered and cursor pagination, keyboard sorting, rich Angular cells, and the empty state.
- Keep `design/select-variants.json` aligned with `goodui.select`, `goodui.select-country`, `goodui.select-option`, and `goodui.select-panel` on `17 Selects`. The first two map to `good-select` and `good-select-country`; option and panel are internal parts of Select. Preserve linked Lucide and Badge instances, semantic `select.*` token bindings, three sizes, selected and disabled states, country flag examples, and both themes. Verify search, single and multiple values, maximum selection, disabled options, keyboard focus, and Angular Forms behavior.
- Keep `design/input-phone-variants.json` aligned with `goodui.input-phone` and its internal `goodui.phone-country` family on `18 Phone Inputs`. The linked country selector belongs to `good-input-phone`. Preserve three sizes and empty, filled, disabled, and error states; verify `phone.*` token bindings, locale fallback, live `+`/`00` calling-code recognition, leading-zero normalization on blur, Angular Forms, and both themes.
- Keep `design/input-variants.json` aligned with the live `goodui.input` and `goodui.input-addon` Penpot variant groups. The 21 Input states and 24 addon options map to `good-input`; the addon is an internal visual part, not another Angular selector. Check linked Lucide instances, token bindings, and both appearance themes after edits.
- Keep `design/pin-input-contract.json` aligned with the `good-pin-input` API. Page `20 PIN Inputs` and `pin.*` tokens exist; `goodui.pin-input` remains pending because the Penpot MCP plugin disconnected during variant construction. Do not invent IDs or claim design parity. Once connected, inspect and clean up any partial shape, create and verify real library variants, update `design/component-map.json`, and check brand/mono, size, filled, masked, disabled, placeholder, and token-bound states in both themes.
- Keep `design/alert-contract.json` and `design/notification-host-contract.json` aligned with the published `goodui.alert` (72 variants), `goodui.notification-host` (four variants), and the Alert actions/dismiss composition on `21 Alerts`. Verify IDs, axes, token bindings, linked Lucide and GoodUI instances, both themes, and Angular projection/dismiss behavior after changes. Penpot cannot add children to a component copy, so the action specimen owns a detached Alert frame while its Button and X remain linked.
- Keep Warning yellow on the shared `color.warning` token in Penpot and generated CSS. Badge, Alert, Rating, and the Color Scheme reference must resolve the same vivid yellow; use `color.warning-foreground` for small text and icon strokes that need stronger contrast.
- `goodui.notifications.unread` on `01 Components` composes linked `goodui.notifications.default` and `goodui.badge` instances. The Badge uses `color=destructive`, `variant=solid`, `shape=pill`, and compact `notification.count.*` token overrides at 16 px. Its label is a centered local override because Penpot does not reflow the copied Badge after resizing. Keep the composition ID in `design/component-map.json`; the Angular bell renders that Badge only while unread messages exist.
- Keep `design/dropdown-variants.json` aligned with the live `goodui.dropdown`, `goodui.dropdown-panel`, and `goodui.dropdown-item` Penpot variant groups. The root family maps to `good-dropdown`; panel and item are internal parts. Preserve linked Button, item, panel, and Lucide instances. Verify placement, focus, hover, submenu, scroll, and both themes when this family changes.
- Keep `design/breadcrumbs-variants.json` aligned with the live `goodui.breadcrumbs` Penpot variant group. Its `style`, `start`, `path`, and `separator` axes map to `good-breadcrumbs` inputs and overflow behavior. Keep Lucide instances linked, token bindings intact, and the ellipsis menu navigable.
- Keep `design/badge-variants.json` aligned with the live `goodui.badge` Penpot variant group on `05 Badges`. Its `color`, `variant`, `shape=pill/square`, and `size=small/default/large` axes map to `good-badge`; Angular also accepts legacy `circle` for `pill` and `medium` for `default`. Leading icon and removable X are content options shown by linked instances. Check all 126 variants, semantic color and size token bindings, and both themes.
- Keep `design/link-variants.json` aligned with the 24 `goodui.link` variants on `08 Cards and Links`. Map appearance, underline behavior, decoration style, and disabled state to `good-link`; verify real navigation, focus, and theme colors.
- Keep `design/card-variants.json` aligned with the 20 `goodui.card`, six `goodui.card-header`, and four `goodui.card-footer` variants on `08 Cards and Links`. Map them to `good-card`, `good-card-header`, and `good-card-footer`; preserve linked Header, Footer, Button, ActionMenu, and Link instances, and verify image clipping and both themes.
- Keep `design/code-block-variants.json` aligned with the five `goodui.code-block` variants on `09 Code`. Map display, line numbers, and preview state to `good-code-block`; preserve linked GoodUI Buttons and token bindings. Verify highlighted languages, clipboard feedback, expansion, inline rendering, and both themes.
- Keep `design/modal-variants.json` aligned with the `goodui.modal`, `goodui.modal-header`, and `goodui.modal-footer` groups on `10 Modals`. Map all presentation, size, footer, description, and action states to their Angular selectors. Preserve linked Header, Footer, GoodUI Button, and Lucide instances. Verify focus, Escape, backdrop clicks and blur, nested dialog restoration, body scrolling, viewport presentation, and both themes.
- Keep `design/action-group-variants.json` aligned with the six `goodui.action-group` variants on `11 Action Groups`. Preserve linked GoodUI Buttons and token-bound flex gaps. Map Penpot horizontal/vertical states and three spacing values to `good-action-group`; verify its responsive stack, wrapping, alignment, and both themes. Button components themselves must not gain external margins to compensate for missing container layout.
- Keep `design/typography-components.json` aligned with the live `12 Typography` Penpot page. HeadingGroup, Prose, and FormField own spacing; linked Heading and Summary instances in MainView preserve their content. Verify Eyebrow, FieldLabel, Separator, InlineImage, and FormField variants against Angular inputs and projected content, including semantic headings, required markers, image alt text, and both themes.
- Keep the linked Lucide artwork inside Button variants scaled with its outer instance. Penpot's plugin resize can change the instance bounds without scaling its 24 px child paths; inspect the rendered 14/16/20 px icons and retain their size and stroke-color token bindings after edits.
- Keep the `goodui.` design ID and `good-` Angular selector prefixes.
- Name child elements semantically. Model Button choices as `variant`, `size`, and `content`; keep focus, hover, and disabled as runtime states rather than decorative copies.
- Keep repeated dimensions and colors as semantic tokens in `layout`. Check measurements against the current GoodUI design and rendered homepage before changing them.
- Use shared radius tokens for control, item, card, compact, and pill corners; preserve each semantic role when values happen to match. Prefer flex or grid for component internals and layout flow. Absolute positioning is reserved for genuine overlays or invisible native controls that require it.
- Check color roles in both Penpot themes, `appearance/light` and `appearance/dark`. Shared dimensions belong in `layout`; `layout-dark` overrides colors only.
- Preserve nesting: `AppLayout` → `SidebarContainer`/`Topbar`/`MainView`; sidebar menu container → items; topbar menu container → items; `MainMenu` → four action components.
- Expanded sidebar items retain nested `SidebarSubmenuGroup` and `SidebarSubmenuItem` instances. Containers own indentation, guide lines, and scrolling; active routes open their ancestors.
- Expanded topbar menus retain `TopbarDropdownMenu`, `TopbarDropdownItem`, and `TopbarSubmenu` instances. Parents with children are chevron triggers; only leaves navigate.
- Inspect actual Penpot instances and rendered/exported states. Report status and limitations accurately.
- After changing tokens, check light and dark themes, nested shell exports, and text contrast. Leave Penpot on light and the `02 Layout` page.
- Refresh `design-tokens/penpot.tokens.json` from the Penpot token export after token edits, run `npm run tokens:generate` and `npm run tokens:check`, and verify the snapshot against the live Penpot catalog. Do not hand-edit `tokens.generated.css` or claim live synchronization.
- The native `.penpot` snapshot workflow is suspended at the user's request while Penpot issue #11554 remains unresolved. Do not require a UI export, `npm run penpot:save`, or `npm run penpot:check` for routine changes, and do not repeatedly report the absent archive. Continue inspecting live Penpot designs, verifying component mappings, and synchronizing token JSON when those sources change. Once native export is verified fixed, restore the workflow in `design/penpot/README.md` before claiming a current archive.

## Reference material

- The Angular `homepage/` contains the public Getting Started content and component examples. `guides/` retains plain Markdown reference material; there is no separate documentation application or documentation build.
- Pages under `Examples` demonstrate complete workflows with only GoodUI layout, control, and content components; Angular form directives and native semantic elements remain appropriate. Every example must show its working template and TypeScript source through GoodUI CodeBlock. If an example needs an app-specific CSS or Tailwind layout rule, stop and identify the missing reusable GoodUI capability before adding that example.
- Keep each homepage example in `homepage/src/app/examples/<example-name>/`, with Angular component classes and templates in separate `.ts` and `.html` files. For the registration example, `npm --prefix homepage run examples:sync` generates the displayed CodeBlock strings from those files; `examples:check` verifies that the displayed source is current.
- Edit Getting Started prose and component markup in `homepage/src/app/getting-started/*.html`. Keep page classes focused on Angular bindings and code sample data; update the matching HTML when a chapter changes.
- Keep `homepage/src/app/getting-started/changelog.html` current for substantial user-facing changes, including new public components and observable behavior changes. Each short entry needs the change date and a link showing the commit hash that introduced it. Omit internal refactors, CI changes, and documentation-only corrections. Commit the feature first so its hash is known, then commit the Changelog update before finishing the task.
- The Penpot ID registry is in `guides/contributing/design-to-code.md`. Keep stable IDs and the component mapping accurate when the design or Angular API changes.
- Verify published Angular examples against `angular/projects/goodui/src/public-api.ts`.

## Implementation

- Derive Angular APIs from `design.md` and the component guides. Use Tailwind CSS **4**. Edit library sources under `angular/projects/goodui/src/`; build its CSS from `src/styles.css`.
- Keep API, token, and Penpot changes synchronized with the homepage usage examples and migration guidance.
- Never edit generated files as the only source of a change. Run `npm run build:homepage`; inspect the homepage in a browser after layout or interaction changes.
